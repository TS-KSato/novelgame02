# 共通部分と作品固有の部分の分け方

ノベルゲーム制作キット（`kit/`）は、「ゼルグの旅人」から共通に使える部分を取り出したものです。この文書は、どこまでが共通で、どこからが作品ごとか、ゼルグ固有の互換処理がどこにあるかを示します。

## 1. 四つの層

| 層 | 場所 | 中身 | 作品ごとに変えるか |
|---|---|---|---|
| 共通エンジン | `kit/engine/` | 画面・進行・保存・既読・AUTO/SKIP・音・CG鑑賞・検証 | 変えない（版を固定して使う） |
| キットの版 | `kit/releases/<版>/` | エンジンを版ごとに写したもの | 作品が使う版を一つ決める |
| 作品データ | `kit/samples/<作品>/game.js` など | 行・場面・選択肢・フラグ・素材・演出 | 作品ごとに書く |
| 検証・制作手順 | `tests/`、`kit/README.md`、この文書 | 試験、手順、制限 | 共通 |

作品データは `window.KIT_GAME` という一つのオブジェクトです。エンジンはその中身を読むだけで、作品の文章や名前を持ちません。

## 2. 共通エンジンが持つもの

- 画面の骨組み：タイトル、作品画面、縦向きの案内、モーダル（セーブ・設定・CG 鑑賞）
- 行の進み：文字の表示、タップ・キーでの送り、選択肢、場面の移動
- AUTO と既読 SKIP：選択肢と未読の文章で止まる
- 保存：作品IDごとの保存キー（`kit:<作品ID>:v1`）、手動セーブ 3 枠、つづきから
- 既読：「行ID＋本文の指紋」。本文が変わった行は既読にならない
- 演出の状態：行IDから、背景・立ち絵・CG・BGM・環境音を求める（`stateAt`）
- 音：Web Audio。音オンのときだけ鳴る。BGM・環境音・効果音の三つの音量
- 検証：作品データの誤り（行IDの重複、存在しない参照など）を、開始前に理由つきで止める

## 3. 作品データが持つもの

作品データに書くのは次の内容だけです。

| 項目 | 書き方 |
|---|---|
| 作品ID・作品名・作品データの版・キットの版 | `id`、`title`、`dataVersion`、`kit` |
| 開始位置 | `start: { scene, line }` |
| 話者の表示名 | `speakers` |
| フラグ | `flags`（型は `boolean` か `enum` のみ） |
| 素材 | `assets`（背景・BGM・環境音・効果音・CG・立ち絵） |
| 場面と行 | `scenes`（行は `id`・`speaker`・`text`） |
| 選択肢と移り先 | 場面の `choices`（`text`・`to`・`set`・`when`） |
| 次の場面 | 場面の `next`（文字列、または `flags` を受け取る関数） |
| 演出 | `cues`（行IDで指定。一つにつき背景・BGM・環境音・効果音・立ち絵・CG のどれか一つ） |
| 旧い版の保存の移し方 | `migrations`（版ごとに、行IDの対応 `lines` とフラグの移行 `flags` を書く） |

## 4. 文字列を評価しない（eval を使わない）

フラグの条件や次の場面の決め方は、作品データの中の**関数**として書きます。エンジンは次のことをしません。

- 文字列を `eval` や `new Function` で実行する
- `setTimeout` に文字列を渡す
- 作品データの文字列を条件式として解釈する

この点は `tests/kit/unit.js` の試験で確かめています（エンジンのソースに `eval`・`new Function` が無いこと）。

フラグの条件を関数で書く例（`sample-a` の場合）：

```js
next: (flags) => (flags.route === 'kind' ? 'ending-kind' : 'ending-cool'),
```

## 5. ゼルグ固有の互換処理（キットに持ち込まない）

次の処理は、ゼルグの公開中の本編にだけ残します。キットには入れません。

| 処理 | ゼルグでの場所 | 理由 |
|---|---|---|
| 旧版の既読の対応表 | `seen-map.js`、`tools/make-seen-map.js` | ゼルグの旧版（full-v8〜v19）の既読を移すための、ゼルグだけの表 |
| 旧版の保存の移行 | `app.js` の `migrateState`、`migrateSeenBase` など | ゼルグの過去の保存形式に固有 |
| 本文の版 | `app.js` の `OPENING_REV` | ゼルグの本文の履歴に固有 |
| 背景・立ち絵の既存テーブル | `backgrounds.js`、`stage.js` の行番号指定 | ゼルグの本文に合わせた設定。キットへの一括変換は今回の対象外 |

新しい作品へ、ゼルグの過去版の移行を持ち込まないでください。新しい作品の旧版の移行は、その作品の `migrations` で、版ごとに明示して扱います。

## 6. 版の扱い

- **キットの版**（例：`0.1.0`）は、`kit/releases/<版>/` の中身で決まります。
- **作品データの版**（例：`2026.10-1`）は、作品ごとに付けます。文章・行・演出を変えたら上げます。
- 作品は、`kit` の欄で使うキットの版を**固定**します。共通エンジンを更新しても、作品は自動では変わりません。新しい版へ移すのは、作品の作者が `kit` を書き換えて行います。

## 7. 既読・保存の分離

- 保存キーは `kit:<作品ID>:v1` です。作品IDは英小文字・数字・ハイフンで、40 字以内です。
- 同じ場所（同じ公開先）に二つの作品があっても、自動セーブ・手動セーブ・既読・CG 解放・設定は互いに読みません。
- これは `tests/kit/browser.js` の「作品ごとの分離」で確かめています。

## 8. 保存の互換性

保存は、保存位置・既読・フラグを分けて扱います。作品の版（`dataVersion`）とフラグの定義が保存の時と同じなら、そのまま使います。違うときは、作品の `migrations` が移し方を明示したものだけを使います。

- **保存位置**：行IDが存在するだけでは使いません。版が同じときは行IDをそのまま使い、版が違うときは `lines` の対応表で写します。`'identity'` は、行IDが変わっていないと作品が明示したときだけ書けます。
- **既読**：「行ID＋本文の指紋」です。現在の行と指紋が一致するものだけ残します。文章を変えた行は、指紋が変わるので未読に戻ります。変わっていない行の既読は、版を移しても残ります。
- **フラグ**：保存時の定義（名前・型・値・既定値）を保存に書き、現在の定義と比べます。違えば `flags` の関数で移します。関数の結果が定義に合わなければ移しません。版を変えずに定義だけ変えたときは、移す方法がないので読みません。

**移せないとき**：保存位置やフラグの一つでも移せなければ、その保存は「移行できない」になります。読まず、書き込みも止めます。元の保存は、そのまま残します。移行に成功したときは、移行の前に元の保存を `kit:<作品ID>:v1:backup:<保存の版>` に一度だけ残します。

行IDを使うと、行を挿入しても演出と保存位置はずれません（`tests/kit/unit.js` と `tests/kit/saves.js` で確かめています）。ただし、行IDや文章を変えたときの既読と保存は、上の対応を作品側で書く必要があります。
