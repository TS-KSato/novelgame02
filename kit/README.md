# ノベルゲーム制作キット（試作 0.1.0）

「ゼルグの旅人」の仕組みから、別の作品でも使える部分を取り出した試作です。短いサンプル作品 2 つで動作を確かめられます。

- 共通エンジン：`kit/engine/`（画面・進行・保存・既読・音・CG 鑑賞・検証。保存の評価は `save.js`）
- サンプル作品：`kit/samples/sample-a/`（分岐・選択肢・背景・立ち絵・CG・音・保存を含む）と `kit/samples/sample-b/`（保存の分離を確かめるための最小の作品）
- 版の固定：`kit/releases/0.1.0/`
- 試験：`tests/`（手順は第 6 節）
- 共通と作品固有の分け方と、保存の考え方：[docs/kit/SPLIT.md](../docs/kit/SPLIT.md)

公開中のゼルグ（リポジトリ直下）は、この試作の影響を受けません。

## 1. 動かす

リポジトリの直下で、次を実行します（先に第 6 節の準備をしてください）。

```sh
npm run serve
```

ブラウザで次を開きます（横向きで見てください）。

- http://127.0.0.1:8080/kit/samples/sample-a/index.html
- http://127.0.0.1:8080/kit/samples/sample-b/index.html

作品の画面は、横向きに固定して使います。縦向きでは案内を出して止まります。

## 2. 作品の構成

```
kit/samples/<作品ID>/
  index.html   キットを読み込み、window.KIT_GAME を起動する（ほぼ固定）
  game.js      作品データ（window.KIT_GAME）。作品の中身はここに書く
  assets/      画像・音声
```

`index.html` は次の形のままで使えます。`releases/0.1.0` の部分だけが、使うキットの版です。

```html
<link rel="stylesheet" href="../../releases/0.1.0/kit.css">
<div id="kit-root"></div>
<script src="../../releases/0.1.0/validate.js"></script>
<script src="../../releases/0.1.0/save.js"></script>
<script src="../../releases/0.1.0/kit.js"></script>
<script src="game.js"></script>
<script>window.KIT = KitEngine.start(window.KIT_GAME);</script>
```

## 3. 新しい作品を作る

1. `kit/samples/sample-a/` を `kit/samples/<新しい作品ID>/` へ丸ごとコピーします（素材も含む）。
2. `game.js` の内容を、新しい作品のものに書き換えます。`id` は必ず新しい値にします（保存が混ざらないように）。
3. `kit` の欄は、使うキットの版（今は `0.1.0`）のままにします。
4. ブラウザで `index.html` を開き、起動を確かめます。作品データに誤りがあると、理由つきの画面が出て止まります。
5. 試験を実行します（第 6 節）。

サンプルの素材は試験用の単純な図形と音です。Zelg の素材は含まれず、複製もしていません。

## 4. 作品データに登録するもの

| 登録するもの | `game.js` の項目 | 書き方 |
|---|---|---|
| 文章 | `scenes.<場面>.lines` | `{ id: '行ID', speaker: '話者キー', text: '本文' }`。行IDは作品全体で一意 |
| 話者（名前） | `speakers` | `{ 話者キー: '表示名' }`。話者のない行は地の文 |
| 場面の名前 | `scenes.<場面>.title` | 画面上部に出る |
| 分岐（選択肢） | `scenes.<場面>.choices` | `{ text, to, set?, when? }`。`set` はフラグの設定、`when` は表示条件（関数） |
| 場面の移動 | `scenes.<場面>.next` | 次の場面名。フラグで決めるなら関数（`(flags) => ...`） |
| フラグ | `flags` | `{ 名前: { type: 'boolean', default: false } }` か `{ type: 'enum', values: [...], default }` |
| 背景 | `assets.backgrounds` と `cues`（`bg`） | 素材を登録し、行IDで指定 |
| 立ち絵 | `assets.portraits` と `cues`（`portrait`） | `{ slot: 'left'｜'right', char, expr }`。`{ slot, clear: true }` で消す |
| CG | `assets.cgs` と `cues`（`cg`） | `{ id, until? }`。`until` まで出し、到達で CG 鑑賞に解放 |
| BGM・環境音 | `assets.bgm`・`assets.ambience` と `cues` | 行IDで指定。同じ曲が続けば止めない |
| 効果音 | `assets.se` と `cues`（`se`） | 行に到達したときに一度だけ鳴る |
| 旧い版の保存の移し方 | `migrations` | 版ごとに、行IDの対応（`lines`）とフラグの移行（`flags`）を書く。第 5 節 |

演出（`cues`）は、一つにつき「背景・BGM・環境音・効果音・立ち絵・CG」のどれか一つだけを書きます。

## 5. 保存と既読の互換

保存は三つに分けて扱います。作品データの版（`dataVersion`）と、フラグの定義（名前・型・値・既定値）が、保存の時と同じかどうかで決まります。

| 対象 | 同じ版・同じ定義 | 版が違う（`migrations` あり） | 移せない |
|---|---|---|---|
| 保存位置（自動・手動） | 行IDをそのまま使う | `lines` で写す。`'identity'` は行IDが変わっていないという作品の明示 | 読まない・書かない |
| 既読 | 「行ID＋本文の指紋」が現在の行と一致するものだけ残す | 写した行IDで照合し、指紋が一致するものだけ残す | 一致するものだけ読む |
| フラグ | 定義どおりに使う | `flags` の関数で移す。定義に合わない結果は移さない | 読まない・書かない |

**移行の条件**：保存の位置とフラグは、すべて移せたときだけ移行します。一つでも移せなければ、その保存は「移行できない」になり、読みません。書き込みも止めて、元の保存をそのまま残します。移行の前には、元の保存を `kit:<作品ID>:v1:backup:<保存の版>` に一度だけ残します。

作品側の書き方（`game.js`）：

```js
migrations: {
  // 版 2026.10-1 の保存を、今の版へ移す
  '2026.10-1': {
    lines: { 'a-001': 'a-001', 'a-003': 'a-003n' }, // 行IDの対応。書いていない行は写さない（その位置の保存は移せない）
    // lines: 'identity',                             // 行IDが変わっていないなら、こう書く
    flags: (f) => ({ ...f, route: f.route === 'kind' ? 'warm' : f.route }), // フラグの定義が変わったときに必須
  },
},
```

- 行IDが変わっていないのに版だけ変えた（文章の修正など）：`lines: 'identity'`。変わった文章の行は、指紋が一致しないので既読になりません。変わっていない文章の既読は残ります。
- 行IDを変えた：対応表（`lines`）に新旧を書きます。書いていない行の保存は移せないので、移行できません。
- フラグの定義が変わった：版を上げ、`flags` の関数で移します。関数の結果が新しい定義に合わなければ、移行できません。
- フラグの定義を、版を変えずに変えた：移行できません。版を上げて、移し方を書いてください。
- 行の挿入・削除だけで、行IDが変わらない場合：版は変えなくてかまいません。保存位置と演出は、行IDで指すので、ずれません。

行IDを使っても、保存の移行が不要になるわけではありません。文章を変えた行の既読、行IDを変えたときの保存、フラグの定義の変更は、上の対応が必要です。考え方は [SPLIT.md の第 8 節](../docs/kit/SPLIT.md#8-保存の互換性) を参照してください。

## 6. 試験

### 準備（初めて取得した環境で、一度だけ）

前提：Node.js 18 以上（`node -v` で確認）。リポジトリの直下で、次を順に実行します。

```sh
npm ci                          # 試験に使う Playwright（版は package.json で固定）
npx playwright install chromium # Playwright の Chromium を取得する（初回のみ）
```

既に別の Chromium を使う場合は、`npx playwright install` の代わりに、その実行ファイルのパスを環境変数で指定します。

```sh
KIT_CHROMIUM_PATH=/path/to/chromium npm test
```

### 実行

```sh
npm test                 # すべて
npm run test:unit        # 作品データの検証・演出の状態・行の挿入・保存の評価・eval 不使用（ブラウザ不要）
npm run test:browser     # サンプルA・Bの操作（進行・選択肢・AUTO・既読SKIP・音・CG・横向き・作品の分離）
npm run test:saves       # 変更前の保存を、変更した作品データで読む（行の挿入・本文の変更・対応表・移せない保存・フラグ）
npm run test:zelg        # ゼルグの起動・新規開始・再開・手動保存と読込・合成した旧版保存の移行（本編のファイルは変えない）
```

試験は、リポジトリの中のファイルだけを使います。一時フォルダや、特定の環境の Playwright の配置には依存しません。保存の試験は、試験の中で作った保存だけを使います。

`npm run test:zelg` のうち、既読の対応表（`seen-map.js`）の確認は git の履歴が必要です。履歴が浅いクローンでは失敗するので、完全なクローンで実行してください。

### 素材と版を作り直すとき

```sh
npm run assets           # kit/samples/*/assets を作り直す（試験用の図形と音）
npm run release          # kit/engine の変更を、kit/releases/<版> に写す（既存の版は上書きしない）
```

## 7. キットの更新を作品へ取り込む

キットの版は、作品ごとに固定されています。新しい版を使うときは、作品の作者が次の手順で行います。

1. `kit/engine/kit.js` の `KIT_VERSION` を上げ、`npm run release` で新しい版のフォルダ（`releases/<新しい版>/`）を作ります。既存の版のフォルダは上書きされません。
2. 作品の `index.html` の `releases/<古い版>/` を `releases/<新しい版>/` に書き換えます。
3. 作品の `game.js` の `kit` の欄を、新しい版にします。
4. 作品の `migrations` に、古い版の保存の移し方を書きます（保存の互換性が変わるとき）。
5. 試験を実行し、作品を動かして確かめます。

共通エンジンを更新しても、既存の作品は自動では変わりません。

## 8. 現在の制限

- 試験はデスクトップ版 Chromium だけで行いました。iPhone・Android の Safari や Chrome では確かめていません。
- 音の再生は Web Audio に依存します。自動再生の制限のあるブラウザでは、最初の操作の後に鳴ります。
- 縦向きの扱いは、画面の向きの判定（`orientation: portrait`）に依存します。
- 素材は PNG と WAV（検証で使う単純な図形と音）だけです。ほかの形式は、`FILE_RE` の許可に加える必要があります。
- 旧い版の保存の移行は、作品が `migrations` に書いたものだけです。自動では写しません。
- 旧い版の作品データの移行表（ゼルグの `seen-map.js` に当たるもの）はキットにありません。必要な作品は、その作品で作ります。
- 場面を跨ぐ CG の区間は、同じ場面の中だけで指定できます。
- ゼルグの既存の本文・背景・立ち絵のテーブルを、キットの形式へ変換する作業は含みません。
- 作品の制作者向けの画面（エディタ）はありません。作品データは手で書きます。
- 設定画面は、文字の速さと三つの音量だけです。
- ゼルグの試験は、起動・新規開始・再開・手動保存と読込・合成した旧版保存の移行を確かめます。実際のプレイヤーの保存は使いません。
- ゼルグの起動時には、移行のバックアップより前に設定の正規化が保存を書き換えることがあります（音量の値など）。進行の記録（自動セーブ・手動セーブ・既読）は変わりません。ゼルグ本体は変更しない方針のため、この挙動は記録にとどめています。
